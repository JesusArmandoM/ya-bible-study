# Architecture

## Overview

**YA Bible Study** is a single-package TypeScript web application serving a mobile-first React SPA, REST endpoints (`/api/*`), and real-time WebSocket synchronization (`/ws`) over **one unified port/origin**. This single-origin topology eliminates CORS/port mismatches across desktop browsers, mobile devices on local Wi-Fi, single-instance cloud containers, and public HTTPS tunnels (`cloudflared` / `ngrok`).

## Module Boundaries & Dependency Direction

```
src/client/  ──imports──▶  src/shared/  ◀──imports──  src/server/
```

- `src/shared/`
  - Pure TypeScript types, constants, and validation contracts shared between browser and server (`src/shared/health.ts`, `src/shared/study.ts`, `src/shared/session.ts`). `src/shared/session.ts` defines the `/ws` protocol contract at `SESSION_PROTOCOL_VERSION = 3` (additive over v2/v1): the sanitized `SessionStudySummary` (title/meta-only — never pastoral fields), `toSessionStudySummary`, `normalizeSessionStudySummary` bounds validation, the bounded participant-only `SessionOpeningPrayerContent` normalization (never `leaderPrompt`), the `VolunteerTurnState` hand-raise queue with pure reducers (`createVolunteerTurnForSection`, `applySetHandRaised`, `applyClearHands`, `applySelectVolunteer`, `applyCompleteTurn`, `applyStageRandomCandidate`, `applyConfirmRandomCandidate` (composes the frozen `applySelectVolunteer`), `applyClearRandomCandidate`, `volunteerTurnModeForSection`, `volunteerTurnPhase` returning `collecting_hands` / `random_pending` / `assigned` / `turn_completed`), the random-selection countdown helpers (`RANDOM_SELECTION_COUNTDOWN_MS = 30_000`, `eligibleRandomCandidateIds` — connected `Participant`s in join order, `remainingCountdownSeconds` — display-only `0..30` clamp over the absolute `candidateExpiresAt`), the `raise_hand` / `lower_hand` / `complete_turn` participant turn commands (`complete_turn` carries `sessionCode` / `memberId` / `requestId` — no turn id — and is NOT a `LeaderCommandType`), the `clear_hands` / `choose_volunteer` (required `targetMemberId`) / `override_turn` / `pick_random` / `retry_random` / `confirm_random` leader commands (`choose_volunteer` / `override_turn` and the random trio widen `LeaderCommandType`; the random trio rides the leader envelope `{ type, sessionCode, leaderToken, memberId? }`; `SessionUpdatedCommand` covers every broadcast command except `close_session` and additionally carries the server-initiated `random_expired` label, which is never accepted from clients), `UNAUTHORIZED_MEMBER`, and the leader-gated `load_study` command, with additive optional `study` / `protocolVersion` / `volunteerTurn` fields on `PublicLiveSessionSnapshot` (older clients keep working).
  - **Allowed imports**: `src/shared/*` only (no DOM globals, no Node built-ins, no `src/client/*` or `src/server/*`).
- `src/server/`
  - Express + Node `http.Server` + `ws` (`WebSocketServer` in `noServer` mode with `maxPayload: 64 * 1024`, handling HTTP `upgrade` exclusively for `/ws`).
  - `src/server/studies/` holds server-side study curriculum providers (`src/server/studies/greatIsYourFaithSeed.ts` exposing immutable preloaded `StudyDocument` clones via `getDefaultStudyDocument()`) and deterministic parsers: `src/server/studies/markdownParser.ts` extracting 5-section `StudyDocument` structures from standard numbered Markdown outlines with Section 8 Gospel reconstruction fallback and zero external AI, and `src/server/studies/pdfParser.ts` extracting and normalizing in-memory text from text-based `.pdf` uploads (`unpdf`) with header/footer/page-number stripping, ligature expansion, smart quote normalization, and heading formatting.
  - `src/server/sessionStore.ts` implements the in-memory `LiveSessionStore` (`create_session`, `join_session`, `claim_leader`, `reconnect_session`, leader lifecycle commands including the state-gated `load_study` (valid in `setup|lobby`, `INVALID_MESSAGE` on malformed summaries, broadcast `session_updated`), `start_study`, `next_section`, and the non-gated `clear_hands`, plus the socket-binding-authenticated `handleTurnCommand` handling `raise_hand` / `lower_hand` / `complete_turn` in `in_progress` + `section_1_prayer` (`UNAUTHORIZED_MEMBER` on unbound sockets, `INVALID_STATE_TRANSITION` on the wrong state, idempotent raise/lower/complete; `complete_turn` is ordered socket-identity → state gate → `selectedMemberId` check → idempotent already-completed no-op → `applyCompleteTurn`), the leader-gated `choose_volunteer` (target validation before the state gate, idempotent same-target re-choose, revoke+reassign on a different target) and `override_turn` (completes the turn from `collecting_hands` or `assigned`, never revokes), the server-enforced `next_section` gate rejecting with `INVALID_STATE_TRANSITION` `'The Opening Prayer turn must be completed before advancing.'` while `currentSectionId === 'section_1_prayer'` and `volunteerTurn?.completedAt == null`, and the `start_study` → `section_1_prayer` volunteer-turn lifecycle (created on `start_study`, cleared on `next_section`), the server-authoritative random-selection countdown (`pick_random` stages a fair candidate + absolute `candidateExpiresAt` via the injected `pickRandomIndex` seam over `eligibleRandomCandidateIds` — empty pool rejects `INVALID_STATE_TRANSITION`; `retry_random` re-rolls excluding the current candidate with a single-Person fallback, resets the window, and stays valid after expiry; `confirm_random` assigns via `applyConfirmRandomCandidate` only while the window is open, with a lazy server-clock expiry check rejecting `INVALID_STATE_TRANSITION` `'The random selection window has expired…'`; one unref'd per-session `randomExpiryTimer` (`randomCountdownMs` option, default `RANDOM_SELECTION_COUNTDOWN_MS`) clears the candidate and broadcasts `session_updated { command: 'random_expired' }`, self-cancelling silently once `selectedMemberId`/`completedAt` supersede the pick; timers are cancelled in `next_section`, `closeAndPurgeSession`, and `dispose`), secret stripping on public snapshots, and 4-hour inactivity TTL sweep). Public snapshots carry `study` (copy), `volunteerTurn` (deep copy), and `protocolVersion: SESSION_PROTOCOL_VERSION`; every accepted command broadcasts a full snapshot with `requestId` echoed to the requester.
  - `src/server/app.ts` exports `createAppServer(options)` wiring `LiveSessionStore` to `/ws`, `GET /api/health` (`activeSessionCount`, `publicUrl` — the sanitized `http(s)` origin from the optional `PUBLIC_URL` tunnel variable, `null` when unset/invalid), `GET /api/studies/default`, and `POST /api/studies/parse` (supporting `.pdf` and `.md` `multipart/form-data` file uploads, raw binary `application/pdf`, raw `text/markdown`, and JSON payloads up to 10MB with HTTP 413/400 validation error handling and non-PDF/non-MD rejection), with deterministic `start(port, host)` and `close()` lifecycle helpers (including TTL timer disposal) so integration tests bind ephemeral port `0` cleanly.
  - `src/server/index.ts` is the production/dev CLI entrypoint binding `PORT` (default `3000`, or `API_PORT=3001` behind Vite in dev).
  - Routing order on the unified port:
    1. Early `Content-Length` ceiling middleware on `POST /api/studies/parse` rejecting requests > 10MB with HTTP 413.
    2. Body parsers (`express.json({ limit: '10mb' })`, `express.text({ limit: '10mb' })`, `express.raw({ type: 'application/pdf', limit: '10mb' })`, and multer memory upload).
    3. Explicit `/api/*` handlers (`GET /api/health`, `GET /api/studies/default`, `POST /api/studies/parse`).
    4. `/api` JSON `404` fallback (`{ "error": "Not found" }`) so mistyped API calls never receive HTML.
    5. Payload error-handling middleware formatting HTTP 413 `{ "error": "File size exceeds 10MB limit" }`.
    6. Built `dist/client` static assets + SPA `index.html` fallback for non-`/api`, non-`/ws` `GET`/`HEAD` requests.
    7. HTTP `upgrade` listener routing `/ws` to `WebSocketServer` and rejecting other upgrade paths with `404`.
  - **Allowed imports**: Node built-ins, server packages (`express`, `ws`), `src/server/*`, and `src/shared/*`. Never `src/client/*`.
- `src/client/`
  - React 19 SPA compiled by Vite into `dist/client`.
  - `src/client/styles/tokens.css` & `src/client/styles/global.css`: Sacred Midnight Sanctuary design tokens (`DESIGN.md`), `440px` mobile-first safe-area column (`100dvh`), ambient radial glows, and `>= 16px` form control baseline.
  - `src/client/lib/runtimeUrl.ts`: Dynamic same-origin `/api/*` and `ws://` / `wss://` URL resolution derived from `window.location`, plus localhost-safe join-link helpers: `isLocalOnlyHostname` (`localhost`, `127.0.0.1`, `[::1]`, `::1` with or without ports), `sanitizeHttpOrigin` (bare `http(s)` origin from `PUBLIC_URL`, path stripped; `null` when unset/invalid), and `resolveJoinUrl` (`{publicUrlOrigin}/join/{code}` when the app runs on a local-only origin and a valid `PUBLIC_URL` is configured, otherwise the untouched `window.location` origin).
  - `src/client/lib/urlHelpers.ts`: Pure URL join code extractor parsing `/join/:code` pathnames and `?code=` / `?join=` query parameters into validated uppercase session codes.
  - `src/client/lib/sessionSocket.ts`: Typed `/ws` session client and role-scoped `sessionStorage` reconnect credential helpers built on `resolveWebSocketUrl`; leader commands include the `load_study`-capable `sendLeaderCommand` (`study` payload on `load_study` only, optional `targetMemberId` on `clear_hands`, required `targetMemberId` on `choose_volunteer`, leader-only `override_turn`) and the participant `sendTurnCommand` (`raise_hand` / `lower_hand` / `complete_turn` with required `memberId`). The three random-selection commands (`pick_random` / `retry_random` / `confirm_random`) need no framing change: they ride the untouched default `sendLeaderCommand` fall-through as no-target leader envelopes.
  - `src/client/lib/useLiveSession.ts`: Reactive React hook bridging `createSessionSocketClient` with state management, automatic credential re-hydration, and room actions (`createRoom`, `joinRoom`, `claimLeadership`, `loadStudy`, `openLobby`, `startStudy`, `setHandRaised`, `lowerHand`, `clearRaisedHands`, `chooseVolunteer`, `completeTurn`, `overrideTurn`, `nextSection`, `leaveRoom`) plus `lastSessionCommand` (the `session_updated.command` of the latest broadcast — drives the `completion-pulse` Sacred3DScene impulse on `complete_turn` / `override_turn`, and the `random-spin` / `confirm-burst` impulses on `pick_random` / `retry_random` / `confirm_random`). The random picker dispatches through `src/client/lib/useRandomSelection.ts`, a thin stateless hook (`pickRandom` / `retryRandom` / `confirmRandom` over the shared client's `sendLeaderCommand`, `session_error` surfacing through the existing error path) — so `sessionSocket.ts` and `useLiveSession.ts` remain behaviorally unchanged for the feature.
  - `src/client/lib/useStudySetup.ts`: Study setup hook fetching the default `StudyDocument` from `GET /api/studies/default`, analyzing uploaded `.pdf` / `.md` study files via multipart `POST /api/studies/parse`, retaining the last valid preview across failed uploads, and surfacing actionable validation errors.
  - `src/client/lib/qrCode.ts`: Client-side, offline QR rendering (`qrcode` dependency, `QRCode.toString(url, { type: 'svg', errorCorrectionLevel: 'M', margin: 2 })`) producing a deterministic, accessible inline SVG (`role="img"`, `aria-label`) for the join URL — zero network calls.
  - `src/client/lib/usePrefersReducedMotion.ts`: Media-query hook synchronizing `(prefers-reduced-motion: reduce)` across 3D and UI motion layers.
  - `src/client/state/sacredStageStore.ts`: Scoped + default `zustand` stage store (`createSacredStageStore`, `useSacredStageStore`, `resolveSacredStage`) with a zero-React-rerender 60fps transient `impulse` channel read directly inside `useFrame`.
  - `src/client/components/stage/`: Persistent single-canvas Three.js PBR hero stage (`Sacred3DScene`, `SacredStageRig`, `sacredStageMath`, `webglSupport`) with offline `RoomEnvironment` studio lighting, 6 procedural stage geometries, pointer tilt spring inertia, background-tab frame pausing, and automatic `SacredFallbackEmblem` SVG/CSS fallback on unavailable or lost WebGL contexts.
  - `src/client/components/welcome/`: Welcome & Role Selection flow components (`WelcomeRoleCards`, `LeaderAccessSheet`, `ParticipantJoinSheet`, `ActiveSessionBanner`) matching `ux/1. Welcome.png` with tactile `motion/react` spring feedback, `>= 16px` inputs, 4-digit PIN claim, and zero "Assistant" copy.
  - `src/client/components/setup/`: Leader Load Your Study setup screen (`LeaderStudySetupScreen`, `StudyUploadDropzone`, `StudyPreviewCard`, `StudyStructureList`) matching `ux/2. Leader Setup.png`, with drag-and-drop / tap file selection, live study preview (Gospel-only Section 3 citation — `StudyStructureList` suppresses the secondary title line on the Gospel row), and `Continue` dispatching the leader-gated `load_study` (sanitized `SessionStudySummary`) then `open_lobby` over `/ws`.
  - `src/client/components/lobby/`: Title Lobby (`TitleLobbyScreen`) shown for session status `lobby` — role-aware (`leader` / `participant`), `YA BIBLE STUDY · LIVE SESSION` chip, liturgical eyebrow, Playfair study title, Gospel-only citation line, live metrics card (`ATTENDEES` = `session.connectedParticipantCount`, `5` sections, `{estimatedMinutes}m`), leader-only `Room Code / QR` share trigger and `Start Study →` CTA (server-gated `start_study`), participant waiting pill, and `Study not loaded yet` fallback when no summary is synced; `RoomCodeShareSheet` bottom sheet with the offline QR SVG, large room code, readonly join-URL field + copy (`aria-live` "Link copied" with selection/`execCommand` fallback), `navigator.share`, and a terracotta localhost warning naming `npm run share` when the link is local-only without `PUBLIC_URL`; `SectionOneHandoff` was replaced by the Section 1 live surface: `src/client/components/sections/SectionProgressHeader.tsx` (shared `SECTION {n} OF 5` / `{percent}%` labels with the 4px gold `role="progressbar"` completion bar) and `src/client/components/prayer/` (`OpeningPrayerScreen`, `OpeningPrayerCard`, `HandRaiseOrb`, `RaisedHandsQueue`, `LockedAdvanceBar`, `SectionPlaceholderScreen` — the neutral `in_progress` placeholder for Sections 2–5) — the Section 1 Opening Prayer live screen shared by both roles, with the participant hand-raise orb → leader first-come queue synchronized over `/ws` and wired to the persistent `Sacred3DScene` (`prayer-orb` stage, `hand-raise` impulse).   - `src/client/App.tsx`: Root Midnight Sanctuary application shell.
  - **Allowed imports**: Browser/React packages, `src/client/*`, and `src/shared/*`. Never `src/server/*`.

## Runtime Surfaces

| Mode | Command | Browser Entry | Routing & WebSocket Path |
| :--- | :--- | :--- | :--- |
| **Development** | `npm run dev` | `http://localhost:5173` | Vite (`allowedHosts: true`) serves HMR client and proxies `/api` + `/ws` (`ws: true`) to `tsx watch` backend on `API_PORT=3001`. |
| **Production** | `npm run build && npm start` | `http://localhost:3000` (`PORT`) | Single Node process (`dist/server/index.js`) serves `dist/client`, `/api/*`, and `/ws` on one port. |
| **Public Tunnel** | `npm run share` | `https://<subdomain>.trycloudflare.com` | `cloudflared` forwards HTTPS + WSS traffic directly to the unified local port. |

## Verification Layers

- **Static (`npm run typecheck`)**: Runs `tsc --noEmit` across `tsconfig.client.json`, `tsconfig.server.json`, and root `tsconfig.json` (including `tests/**`).
- **Unit & Integration (`npm test`)**: Vitest suites under `tests/unit/` (`node` + `jsdom`) and `tests/integration/` (ephemeral single-port HTTP + `/ws` server tests).
- **End-to-End (`npm run test:e2e`)**: Playwright (`playwright.config.ts`) builds the production bundle, starts `npm start` on an isolated single port, and runs mobile-viewport (`390x844`) Chromium verification under `tests/e2e/`.
- **Startup Gate (`./init.sh`)**: Non-blocking executable baseline running dependency check, `npm run typecheck`, `npm test`, and `npm run build`.
